01 · O sistema que vamos construir

Hoje vamos construir um cadastro de alunos com nome, e-mail e curso. O usuário preenche o formulário, o JavaScript envia os dados ao backend e o backend grava no SQLite. Ao final, a própria página consulta e exibe os cadastros.

Este é seu primeiro sistema web completo: frontend + API + banco de dados. Não exige React, Expo nem conhecimento das práticas anteriores. Use dados fictícios durante a aula.

Siga um backend por vez: Python com Flask é o percurso principal. Node.js com Express é uma alternativa completa ao final. Os dois usam os mesmos três arquivos do frontend e o mesmo formato de tabela.

Escopo: criar e consultar registros (as operações C e R de CRUD). Editar e excluir ficam como desafio orientado. Cadastro de pessoas não é cadastro de contas: não implementaremos senha ou login.

03 · Entender frontend, backend e banco

HTML + CSS + JS no navegador
↓ POST /api/alunos com JSON
Python/Flask ou Node/Express
↓ INSERT com parâmetros
Arquivo cadastros.db (SQLite)
↑ SELECT → JSON → lista na tela
  • HTML: estrutura, campos, rótulos e botões.
  • CSS: aparência, espaçamento e adaptação ao celular.
  • JavaScript: intercepta o envio e usa fetch para conversar com a API.
  • Backend: recebe HTTP, valida os dados e executa SQL.
  • SQLite: motor de banco que grava em um arquivo local. SQL é a linguagem das consultas.

O navegador não abre o arquivo .db. Somente o backend acessa o banco. JSON é o formato de troca de dados, não o banco de dados. API é a interface HTTP que combina endereço, método e resposta.

Método e rotaEntradaSaída
GET /NenhumaPágina HTML
GET /api/alunosNenhuma200 e uma lista JSON
POST /api/alunosJSON: nome, email, curso201 e o novo aluno; 400 para dados inválidos; 409 para e-mail repetido

07 · Desenhar o banco e compreender SQL

A tabela alunos tem uma linha por cadastro. id identifica o aluno; email não pode se repetir. COLLATE NOCASE ajuda a tratar diferenças de maiúsculas no e-mail ASCII. A aplicação também normaliza o e-mail para minúsculas.

SQL explicativo — o backend executará essas instruções
CREATE TABLE IF NOT EXISTS alunos (
  id INTEGER PRIMARY KEY,
  nome TEXT NOT NULL CHECK(length(trim(nome)) BETWEEN 2 AND 80),
  email TEXT NOT NULL UNIQUE COLLATE NOCASE,
  curso TEXT NOT NULL CHECK(length(trim(curso)) BETWEEN 2 AND 80)
);

INSERT INTO alunos (nome, email, curso) VALUES (?, ?, ?);
SELECT id, nome, email, curso FROM alunos ORDER BY id DESC;

Não execute esse bloco no PowerShell. CREATE prepara a tabela sem apagá-la se já existir; INSERT grava; SELECT consulta. O id é atribuído pelo SQLite quando omitido. Não presuma numeração sem intervalos.

Os pontos de interrogação recebem parâmetros separados do texto SQL. Assim um nome como Ana d'Ávila continua sendo um valor. Não concatene os campos digitados em comandos SQL. O commit confirma a gravação; no Python o bloco with banco confirma ao terminar com sucesso e reverte em caso de erro.

08 · Escrever o backend Python completo

Copie o conteúdo completo, sem as marcações do manual. Baixar app.py

app.py
from pathlib import Path
import re
import sqlite3
from contextlib import closing
from flask import Flask, jsonify, request

BASE = Path(__file__).resolve().parent
DATABASE = BASE / 'cadastros.db'
app = Flask(__name__, static_folder='public', static_url_path='')
app.config['MAX_CONTENT_LENGTH'] = 16 * 1024


def conectar():
    banco = sqlite3.connect(DATABASE)
    banco.row_factory = sqlite3.Row
    return banco


def preparar_banco():
    with closing(conectar()) as banco, banco:
        banco.execute('''CREATE TABLE IF NOT EXISTS alunos (
            id INTEGER PRIMARY KEY,
            nome TEXT NOT NULL CHECK(length(trim(nome)) BETWEEN 2 AND 80),
            email TEXT NOT NULL UNIQUE COLLATE NOCASE,
            curso TEXT NOT NULL CHECK(length(trim(curso)) BETWEEN 2 AND 80)
        )''')


@app.get('/')
def inicio():
    return app.send_static_file('index.html')


@app.get('/api/alunos')
def listar():
    with closing(conectar()) as banco:
        alunos = banco.execute('SELECT id, nome, email, curso FROM alunos ORDER BY id DESC').fetchall()
    return jsonify([dict(aluno) for aluno in alunos])


@app.post('/api/alunos')
def cadastrar():
    dados = request.get_json(silent=True)
    if not isinstance(dados, dict):
        return jsonify(erro='Envie um objeto JSON válido.'), 400
    if any(not isinstance(dados.get(campo), str) for campo in ('nome', 'email', 'curso')):
        return jsonify(erro='Nome, e-mail e curso devem ser textos.'), 400
    nome, email, curso = (dados[campo].strip() for campo in ('nome', 'email', 'curso'))
    email = email.lower()
    if not (2 <= len(nome) <= 80 and 2 <= len(curso) <= 80):
        return jsonify(erro='Nome e curso precisam ter de 2 a 80 caracteres.'), 400
    if len(email) > 120 or not re.fullmatch(r'[^\s@]+@[^\s@]+\.[^\s@]+', email):
        return jsonify(erro='Informe um e-mail válido com até 120 caracteres.'), 400
    try:
        with closing(conectar()) as banco, banco:
            cursor = banco.execute('INSERT INTO alunos (nome, email, curso) VALUES (?, ?, ?)',
                                   (nome, email, curso))
            aluno_id = cursor.lastrowid
    except sqlite3.IntegrityError:
        return jsonify(erro='Este e-mail já está cadastrado.'), 409
    return jsonify(id=aluno_id, nome=nome, email=email, curso=curso), 201


@app.errorhandler(413)
def muito_grande(erro):
    return jsonify(erro='O corpo da requisição excedeu o limite.'), 413


if __name__ == '__main__':
    preparar_banco()
    app.run(host='127.0.0.1', port=3000, debug=False)

Leia o código antes de seguir

  • Path fixa o caminho do banco ao lado de app.py, mesmo se o comando partir de outra pasta.
  • conectar cria uma conexão; closing garante seu fechamento.
  • preparar_banco cria a tabela na inicialização.
  • app.get e app.post associam funções às rotas HTTP.
  • get_json recebe o objeto enviado pelo navegador; a validação do servidor funciona mesmo sem o formulário.
  • jsonify transforma os dados em resposta JSON.
  • O bloco try trata a restrição de e-mail único; a transação evita gravação parcial.
  • public é a única pasta de arquivos estáticos. O arquivo .db fica fora dela.

12 · Conectar o frontend à API

Copie o conteúdo completo, sem as marcações do manual. Baixar public/script.js

public/script.js
const form = document.querySelector('#cadastro');
const lista = document.querySelector('#lista');
const mensagem = document.querySelector('#mensagem');
const salvar = document.querySelector('#salvar');

function avisar(texto, erro = false) {
  mensagem.textContent = texto;
  mensagem.dataset.erro = String(erro);
}

async function listar() {
  const resposta = await fetch('/api/alunos');
  if (!resposta.ok) throw new Error('Não foi possível carregar a lista.');
  const alunos = await resposta.json();
  lista.replaceChildren();
  if (alunos.length === 0) {
    const item = document.createElement('li');
    item.textContent = 'Nenhum aluno cadastrado ainda.';
    lista.append(item);
  }
  for (const aluno of alunos) {
    const item = document.createElement('li');
    item.textContent = `${aluno.nome} — ${aluno.email} — ${aluno.curso}`;
    lista.append(item);
  }
}

form.addEventListener('submit', async (evento) => {
  evento.preventDefault();
  if (salvar.disabled) return;
  salvar.disabled = true;
  avisar('Salvando…');
  try {
    const dados = Object.fromEntries(new FormData(form));
    const resposta = await fetch('/api/alunos', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(dados),
    });
    const resultado = await resposta.json();
    if (!resposta.ok) throw new Error(resultado.erro || 'Não foi possível cadastrar.');
    form.reset();
    avisar('Aluno cadastrado com sucesso!');
    try { await listar(); }
    catch { avisar('Cadastro salvo, mas a lista não atualizou. Clique em Atualizar lista.', true); }
  } catch (erro) {
    avisar(erro.message || 'Confira se o servidor está ligado.', true);
  } finally {
    salvar.disabled = false;
  }
});

document.querySelector('#atualizar').addEventListener('click', () => {
  listar().then(() => avisar('Lista atualizada.')).catch(erro => avisar(erro.message, true));
});
listar().catch(() => avisar('Não foi possível carregar. Confira se o servidor está ligado.', true));

Como o envio funciona

  1. submit dispara quando o formulário é enviado; preventDefault impede a navegação padrão.
  2. FormData coleta os campos e Object.fromEntries monta um objeto.
  3. JSON.stringify transforma o objeto em texto JSON.
  4. fetch envia POST e Content-Type informa o formato ao servidor.
  5. await aguarda cada resposta; resposta.ok verifica códigos de sucesso. fetch não lança erro automaticamente em um HTTP 400 ou 409.
  6. Ao receber 201, o formulário limpa e a lista é consultada novamente.
  7. textContent exibe os nomes como texto, sem interpretar HTML digitado pelo usuário.
  8. finally reabilita o botão mesmo se ocorrer uma falha.

O endereço relativo /api/alunos usa o mesmo servidor que entregou o HTML. Assim não precisamos de CORS nem de duas portas. Não abra esta tela por file:// ou Live Server.

Copie o conteúdo completo, sem as marcações do manual. Baixar server.cjs

server.cjs
const express = require('express');
const path = require('node:path');
const { DatabaseSync } = require('node:sqlite');
const app = express();
const db = new DatabaseSync(path.join(__dirname, 'cadastros.db'));
db.exec(`CREATE TABLE IF NOT EXISTS alunos (
  id INTEGER PRIMARY KEY,
  nome TEXT NOT NULL CHECK(length(trim(nome)) BETWEEN 2 AND 80),
  email TEXT NOT NULL UNIQUE COLLATE NOCASE,
  curso TEXT NOT NULL CHECK(length(trim(curso)) BETWEEN 2 AND 80)
)`);
app.use(express.json({ limit: '16kb' }));
app.use(express.static(path.join(__dirname, 'public')));
app.get('/api/alunos', (req, res) => {
  res.json(db.prepare('SELECT id, nome, email, curso FROM alunos ORDER BY id DESC').all());
});
app.post('/api/alunos', (req, res) => {
  const dados = req.body;
  if (!dados || ['nome', 'email', 'curso'].some(campo => typeof dados[campo] !== 'string')) {
    return res.status(400).json({ erro: 'Nome, e-mail e curso devem ser textos.' });
  }
  const nome = dados.nome.trim();
  const email = dados.email.trim().toLowerCase();
  const curso = dados.curso.trim();
  if (nome.length < 2 || nome.length > 80 || curso.length < 2 || curso.length > 80) {
    return res.status(400).json({ erro: 'Nome e curso precisam ter de 2 a 80 caracteres.' });
  }
  if (email.length > 120 || !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
    return res.status(400).json({ erro: 'Informe um e-mail válido com até 120 caracteres.' });
  }
  try {
    const resultado = db.prepare('INSERT INTO alunos (nome, email, curso) VALUES (?, ?, ?)').run(nome, email, curso);
    res.status(201).json({ id: Number(resultado.lastInsertRowid), nome, email, curso });
  } catch (erro) {
    if (erro.code?.startsWith('ERR_SQLITE') && erro.message.includes('UNIQUE')) {
      return res.status(409).json({ erro: 'Este e-mail já está cadastrado.' });
    }
    throw erro;
  }
});
app.use((erro, req, res, next) => {
  if (erro.type === 'entity.parse.failed') return res.status(400).json({ erro: 'JSON inválido.' });
  if (erro.type === 'entity.too.large') return res.status(413).json({ erro: 'Corpo muito grande.' });
  console.error(erro);
  res.status(500).json({ erro: 'Erro interno. Confira o terminal do servidor.' });
});
app.listen(3000, '127.0.0.1', () => console.log('Abra http://127.0.0.1:3000'));
Terminal — execute uma linha por vez
node server.cjs

Abra o mesmo endereço http://127.0.0.1:3000. Repita todos os testes da seção anterior. Pare Python antes de iniciar Node. Os dois usam o mesmo cadastros.db quando os arquivos estão na mesma pasta; isso permite comparar implementações sem apagar os registros.

DatabaseSync executa operações síncronas: é uma escolha simples para uma aula local com poucos dados. As consultas usam prepare e parâmetros; Express recebe JSON e serve public. O middleware final converte erros em respostas JSON.

Ao retomar em outro computador, leve package.json e package-lock.json e execute npm.cmd ci. Não envie node_modules nem um banco contendo dados pessoais ao repositório.

18 · Atividade, desafios e entrega

Atividade principal

Personalize o sistema para cadastro de participantes de uma oficina. Mude textos, cores e exemplos sem quebrar o contrato nome/email/curso. Cadastre três registros fictícios e demonstre a persistência.

Desafios progressivos

  1. Adicionar contador de alunos usando o tamanho da lista.
  2. Filtrar os alunos na tela por nome usando os dados já consultados.
  3. Adicionar telefone: atualizar HTML, validação, SQL e resposta. Uma tabela existente não ganha a coluna só por alterar CREATE TABLE IF NOT EXISTS: planeje uma migração com ALTER TABLE e backup.
  4. Implementar DELETE /api/alunos/:id com confirmação e DELETE FROM alunos WHERE id = ?. Validar id e retornar 404 se não existir.
  5. Implementar edição com PUT, validar os mesmos campos e atualizar com WHERE id = ?. Testar duplicidade e registro inexistente.

Entrega

Entregue public com os três arquivos, o backend escolhido e os arquivos de dependências correspondentes. Inclua README com como instalar, iniciar, abrir e testar. Não entregue .venv, node_modules ou dados pessoais reais. Anexe evidências de cadastro, erro de duplicidade e persistência após reinício.
